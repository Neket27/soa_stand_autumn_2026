# Security & Compliance

## Классификация данных [🟢 Абсолютно уверен (≈100-80%)]
- В стенде **нет ПДн и реальных денег**: `user_id` — синтетические (`u-1`…`u-20`), товары — `sku-1`…, суммы — тестовые центы. Payment/Inventory — заглушки, банк не настоящий.
- Единственный чувствительный артефакт — админ-токен заглушек `.mocks-token` (управление `/admin/*`): создаётся Makefile локально, права 600, в git не попадает.
- Каждый прогон (в т.ч. в форке) отправляет в аналитику курса сводку: репозиторий, коммит, логин GitHub, статусы сценариев, список изменённых файлов. **Код не отправляется** (GRADING.md).

## Запреты
- **Секреты в репозиторий не committing**: ни токен заглушек, ни строки подключения, ни пароли. `DATABASE_URL` содержит учётку стенда — только в docker-compose/окружении, не в коде и не в логах.
- **Orders не обращается в `/admin/*` заглушек**: это API раннера, токен сервису не выдаётся; попытки «управлять стендом из сервиса» — нарушение модели.
- **Не логировать** строки подключения и тела запросов целиком (достаточно order_id, status, amount_cents).
- **Не менять** привилегии контейнеров в compose (`cap_drop`, `no-new-privileges`) — в любом случае compose трогать нельзя.

## Зоны без автономии агента
- **Всё, кроме `orders/`, — read-only**: mocks/, runner/, cmd/, .github/, .etc/, Makefile, docker-compose.yml, contracts/, docs/, README.md, GRADING.md. Любое изменение проваливает задание на CI — не «аккуратно», а запрещено полностью.
- `contracts/*.yaml` — контракт, от которого вы зависят: читать, не править.

## Аудит
- Официальный аудит — CI курса (workflow `soa-grade`): сверка файлов с baseline (только `orders/`, без symlink), сборка образа, прогон сценариев, check `task_1` в PR.
- Локальная сверка: `git status` / `git diff --name-only` перед коммитом; прогон — `make scenarios TASK=1`.
- Защита устная (5–10 мин): вы отвечаете за решение — каждый механизм (идемпотентность, реконсиляция, тайм-ауты) должен быть объясним.
