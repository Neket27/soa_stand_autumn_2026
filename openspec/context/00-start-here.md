# Start Here

Ты работаешь с продуктом: учебный стенд курса «Архитектура микросервисов и SOA — осень 2026» (репозиторий `soa_stand_autumn_2026`).

## Основная цель продукта
Написать сервис **Orders** (оформление заказов маркетплейса) на Java так, чтобы задание 1 «Деньги не списываются дважды» прошло: сценарии раннера S1–S5 — `PASS`, уровень «полностью». Срок сдачи — 26.10, 23:59 МСК.

## Перед началом любой задачи
1. Прочитай 01-product-context.md (что проверяется и что нельзя ломать).
2. Сверься с 03-architecture.md (инварианты) и 07-anti-patterns.md (запреты).
3. Контракт API — в `contracts/*.yaml` (OpenAPI): это источник правды, а не README.
4. Не изменяй ничего, кроме каталога `orders/` — любое изменение вне него проваливает задание.
5. Не хватает контекста — сформулируй, какого, и не угадывай.

## Главные запреты
- Не менять каталоги и файлы вне `orders/` (mocks/, runner/, cmd/, .github/, .etc/, Makefile, docker-compose.yml, contracts/, docs/, README.md, GRADING.md): CI сверяет diff с baseline и проваливает задание при любом отличие.
- Символические ссылки запрещены везде, включая `orders/`.
- Не коммитить секреты (токены, пароли); `.mocks-token` остаётся вне git.
- Не использовать анти-паттерны из 07-anti-patterns.md (повторы запросов в Payment без Idempotency-Key, синхронное ожидание Payment дольше 1 с, 5xx на POST /orders).
- Не подгонять решение под «открытые» параметры сценариев (`runner/params/task1.json`): на проверке другие числа.
- Если описание в _raw/документах расходится с актуальным кодом — верь коду и подними вопрос.
