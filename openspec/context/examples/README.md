# Examples

## Good
- `contracts/orders.yaml` — точный контракт вашего сервиса (эндпоинты, статусы, коды): единственный источник правды по API.
- `contracts/payment.yaml` — контракт Payment, особенно блок Idempotency-Key (семантика 200/201/422) — основа решения.
- `examples/go/main.go` и `examples/python/main.go` — наивные реализации: полезны как образец «что работает без отказов» (эндпоинты, env-переменные, схема БД, healthz).

## Bad
- `orders/main.go` (текущее содержимое — копия наивного Go-примера): `charge()` без Idempotency-Key (двойные списания на S2/S5), `call()` без тайм-аутов (бюджет 1 с на S3/S4), `fail()` с 5xx (нарушение контракта). Не воспроизводить эти три паттерна в Java-реализации.

## Preferred pattern
Минимальный эталон обращения к Payment (псевдокод):
1. `POST /payments` с заголовком `Idempotency-Key: <order_id>` и коротким тайм-аутом; тело всегда одно и то же для заказа.
2. `201`/`200` — списание выполнено (запомнить `charge_id`/факт) → `paid`.
3. `402` — банк отклонил → снять резерв, `rejected`.
4. Сетевая ошибка / тайм-аут / нет ответа — исход неизвестен → `GET /payments?order_id=<order_id>`: есть списание → `paid`; нет → повтор с тем же ключом (с backoff, с учётом бюджета во время блэк-хола).
5. Пока исход неизвестен — заказ `pending` в БД, фоновый цикл доводит его до `paid`/`rejected`.
