# ADR-001: Язык и стек сервиса Orders — Java 21 + Spring Boot 3

## Status: Accepted

> **Ревизия (2026-10-05).** Изначально выбрано Java 17 (на dev-машине был только 17). Решение
> пересмотрено на **Java 21**: актуальный LTS, доступны виртуальные потоки. Важно: виртуальные
> потоки используются **на стороне обработки HTTP-запросов** (`spring.threads.virtual.enabled=true`),
> а фоновая обработка **остаётся ограниченным пулом** — неограниченные потоки на каждый pending-заказ
> слили бы бюджет S4 (лимит запросов к Payment в блэк-холе). Для локальных `mvn test`/IDEA нужен
> JDK 21; сборка в Docker задаётся `Dockerfile` и от локального JDK не зависит.

## Context
Курс допускает реализацию Orders **на любом языке** (README: «Python, Java, Kotlin, C#, Go, TypeScript и др.») — раннер проверяет систему как чёрный ящик по HTTP-контракту, язык не видит.
Исполнитель — senior Java-разработчик. Инфраструктура стенда (mocks, runner) написана на Go, но является read-only и на язык сервиса не влияет.

## Decision
Сервис Orders реализовывать на **Java 21 (Temurin, LTS)**:
- **Spring Boot 3.x (3.3+)** — HTTP-эндпоинты (`spring-boot-starter-web`), доступ к БД (`spring-boot-starter-jdbc` + HikariCP; JPA — альтернатива, выбор отложен до design — см. 03-architecture.md «Открытые вопросы»).
- **Maven** — сборка и локальные тесты (`orders/pom.xml`).
- **PostgreSQL 16** — драйвер `org.postgresql:postgresql`; база `orders` из `DATABASE_URL`, схема создаётся сервисом при старте.
- **Docker** — multi-stage образ в `orders/Dockerfile`: сборка Maven-образом `maven:3.9-eclipse-temurin-21`, рантайм — JRE 21 (`eclipse-temurin:21-jre`, alpine-вариант допустим). Образ собирается командой `docker build orders/` без аргументов и слушает порт из `PORT`.

## Consequences
- Разработка в знакомом стеке; типовые инструменты (Maven, IDEA, Spring Initializr).
- Образ тяжелее Go-примера (порядок 100–300 МБ против ~20 МБ) — ограничений по размеру образа в задании нет, не критично.
- Локальная проверка логики — `mvn test` без Docker; итоговая проверка — только через стенд (`make scenarios`).
- Spring Boot поднимает собственный web-сервер на `PORT` — healthz и эндпоинты контракта покрываются одним контекстом.

## Alternatives considered
- **Go** (как наивный пример и сам стенд) — минимальный образ, но не основной стек разработчика; отклонено.
- **Чистая Java без Spring (JDK HttpClient + JDBC + встроенный сервер)** — легче и прозрачнее, но больше кода на склейку; отклонено как менее популярный/типовой путь для senior Java-разработчика.
- **Kotlin + Spring Boot** — эквивалентно по стеку, но другой язык; отклонено.
- **Java 17** — LTS, был установлен на dev-машине на старте; отклонено при ревизии 2026-10-05: выбран 21 (актуальный LTS, виртуальные потоки для обработки запросов). Производительности для задачи это не прибавляет (конкурентность низкая, бюджет 1 с держит архитектура), но версия актуальнее и задаёт стек на будущее.

## Review date
Перед первой успешной сборкой `docker build orders/` и запуском `make up` — подтвердить, что образ поднимается и `GET /healthz` отвечает 200 в рамках 2 минут (лимит раннера).
