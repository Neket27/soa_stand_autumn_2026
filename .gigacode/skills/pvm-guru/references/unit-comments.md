# Комментарии юнита Task Tracker

Использовать этот файл, когда пользователь просит посмотреть комментарии задачи, обсуждение, вопросы, замечания, историю уточнений или контекст согласований по SWTR-юниту.

## Поддерживаемый метод

В рамках навыка поддерживается только чтение списка комментариев юнита:

```http
POST /rest/api/unit-comment/v1/find
Accept: application/json
Content-Type: application/json
Authorization: value from local secret
```

Тело запроса:

```json
{
  "unitCode": "PVM-119134"
}
```

Методы создания, удаления, восстановления и редактирования комментариев в этом навыке не использовать. Если пользователь просит изменить комментарии, явно сказать, что текущий навык предназначен только для безопасного чтения комментариев.

## Скрипт

Для получения и нормализации комментариев использовать:

```bash
python3 $SKILL_DIR/scripts/swtr_unit_comments.py PVM-119134
```

Можно передать SWTR-ссылку вместо кода, скрипт сам извлечет код юнита:

```bash
python3 $SKILL_DIR/scripts/swtr_unit_comments.py 'https://portal.works.prod.sbt/swtr/wiki/unit/PVM-119134?space=PVM&tenant=default&suite=wiki_page'
```

Дополнительные параметры:

- `--include-deleted` — включить удаленные комментарии в `normalized.comments`; сырой `response` всегда содержит все, включая удаленные.
- `--page` и `--size` — добавить в тело запроса объект пагинации, если конкретная инсталляция API это поддерживает. По умолчанию скрипт отправляет ровно `{"unitCode": "..."}`.
- `--base-url` — переопределить базовый URL SWTR.
- `--env-file` — указать файл с локальными секретами, по умолчанию `~/.swtr-review.env`.
- `--timeout` — таймаут HTTP-запроса.

## Что возвращается

Скрипт печатает один JSON-объект в stdout:

- `ok` — `true`/`false`;
- `unitCode` — распознанный код юнита;
- `fetchedAt` — ISO-таймстамп вызова;
- `request` — `{url, method, headers, body, skipTlsVerify}`, headers с `Authorization`/`Cookie` redacted;
- `response` — сырой ответ API;
- `normalized` — `{pageSize, hasNext, pageNumber, totalElements, comments, totalOnPage, deletedOnPage, includeDeleted}`. `normalized.comments` содержит читаемый текст, автора, статус удаления и `rawCommentText` для каждого комментария.

## Особенности поля commentText

`commentText` может приходить в двух форматах:

1. обычная строка:

```text
Текст комментария
```

2. строка с JSON-документом редактора, например:

```json
{"type":"doc","content":[{"type":"paragraph","content":[{"type":"text","text":"комментарий 2 чуть длиннее"}]}]}
```

Скрипт пытается распарсить оба варианта. Для JSON-документа он извлекает текст из узлов `text`, превращает `hardBreak` в перевод строки и сохраняет исходное значение в `rawCommentText`.

## Как использовать комментарии в ревью

Комментарии не заменяют описание задачи и wiki-body. Их нужно использовать как дополнительный источник контекста:

- находить открытые вопросы заказчика, архитектора, SO, аналитика или разработчиков;
- проверять, не были ли в комментариях уточнены требования, критерии приемки, ограничения, сроки или владельцы;
- отделять подтвержденные факты от обсуждений и неподтвержденных гипотез;
- выносить нерешенные вопросы в раздел «Открытые вопросы» итогового отчета;
- не считать комментарий изменением постановки, если он противоречит актуальному описанию задачи и не подтвержден в Description/wiki/атрибутах.

## Пример использования в анализе

1. Получить основной источник задачи:

```bash
python3 $SKILL_DIR/scripts/fetch_swtr_sources.py PVM-119134
```

2. Получить комментарии:

```bash
python3 $SKILL_DIR/scripts/swtr_unit_comments.py PVM-119134
```

3. Читать stdout-выводы обоих скриптов вместе: `source` от `fetch_swtr_sources.py` и `normalized.comments` от `swtr_unit_comments.py`.

4. В итоговом отчете указывать, какие выводы взяты из комментариев. Если комментарии не получены из-за `401`, `403`, `404` или `500`, отметить ограничение ревью.

## Ошибки

Типовые ошибки:

- `400` — некорректный запрос, проверить `unitCode` и структуру тела;
- `401` — не настроен или истек локальный секрет авторизации;
- `403` — нет прав на чтение комментариев юнита;
- `404` — юнит или связанный объект не найден;
- `500` — серверная ошибка, приложить `exceptionUUID` из ответа, если он есть.

Секреты авторизации, cookie и токены нельзя сохранять в отчет и нельзя показывать пользователю.
