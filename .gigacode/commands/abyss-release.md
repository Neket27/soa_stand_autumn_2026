> Путь к скрипту ниже подставляет bootstrap-шаг установки. Если вместо пути в
> тексте остался плейсхолдер в двойных фигурных скобках — шаг не выполнялся:
> определи каталог навыка по правилу «Каталог навыка» из его `SKILL.md` и
> подставь сам, путь не выдумывай.

Создай релизную иерархию по workflow скилла **abyss-release**.

Аргументы (`$ARGUMENTS`): `<КОМПОНЕНТ> <ВЕРСИЯ> [--project <КЛЮЧ>] [--dry-run] [--epic <КЛЮЧ>] [--yes]` — например `LGDB 5.2.10`.

Шаг 1 — разбери аргументы. Компонент приведи к верхнему регистру. Если компонент
или версия не переданы — **спроси у пользователя** и не подставляй значения по
умолчанию: ошибка в них создаёт восемь задач с неверными названиями. Проект по
умолчанию — `PVM`.

Шаг 2 — покажи план. Пишущих запросов на этом шаге не уходит:

```bash
python3 ".gigacode/skills/abyss-release/scripts/abyss_release.py" plan \
  --component <КОМПОНЕНТ> --version <ВЕРСИЯ> [--project <КЛЮЧ>] [--epic <КЛЮЧ>]
```

Дальше действуй по `SKILL.md` скилла **abyss-release** (вызови инструментом `skill`):

1. Непустой `environment.problems` — стоп: назови пользователю, чего именно нет
   (проект, тип задачи, тип связи). Ничего не создавай.
2. Непустой `warnings` — покажи и спроси подтверждение. Номер релиза не по маске
   X.X.XX это не блокирует, но требует явного «да».
3. Покажи пользователю поле `table` из вывода **как есть** и дождись
   подтверждения. Своё дерево не рисуй: нарисованная от руки таблица
   неотличима от настоящей и обесценивает подтверждение. При `--dry-run`
   закончи здесь. При `--yes` подтверждение пропусти.
4. По подтверждению создай:

   ```bash
   python3 ".gigacode/skills/abyss-release/scripts/abyss_release.py" execute \
     --component <КОМПОНЕНТ> --version <ВЕРСИЯ> [--project <КЛЮЧ>] [--epic <КЛЮЧ>] --execute
   ```

   Версия не по маске и пользователь подтвердил — добавь `--allow-odd-version`.
5. Верни отчёт на русском: таблицу `Тип | Summary | Ключ | Ссылка | Результат`,
   а также что создано, что переиспользовано и все ли связи `verified: true`.

Состав иерархии зафиксирован в `.gigacode/skills/abyss-release/references/hierarchy.md`, шаблоны
описаний — в `.gigacode/skills/abyss-release/assets/templates.md`. Названия посимвольны: не
редактируй их, не переводи ярлыки в скобках и не унифицируй регистр — по
совпадению названия повторный запуск узнаёт уже созданное.

Ничего не создавай без `--execute`. В трекер пишет только скрипт навыка: ручное
создание юнитов и связей снимает проверки направления связи, идемпотентности и
подтверждения чтением. Если скрипт завершился ошибкой — покажи его вывод
(`failed` с кодом и сообщением внешней системы) целиком, перечисли уже созданное
и предложи до-создание через `--epic`; данные не выдумывай.
