> Пути к скриптам ниже подставляет bootstrap-шаг `install.mjs`. Если вместо пути
> в тексте остался плейсхолдер в двойных фигурных скобках — шаг не выполнялся: определи каталог навыка по правилу
> «Каталог навыка» из его `SKILL.md` и подставь сам, путь не выдумывай.

Покажи человеку его профиль умолчаний и помоги поправить его разговором. Профиль —
локальный файл `~/.config/pvm-guru/profile.json`; из него скрипты навыка берут значения,
когда пользователь их не назвал явно.

Отвечай по-русски, коротко. Каждый шаг заканчивай одним вопросом и жди ответа.
Аргумент команды (`$ARGUMENTS`) — уже названная правка («сделай основным пространством CRPV»):
если он есть, карту всё равно покажи, но вопрос «что менять» не задавай — применяй названное.
Исключение одно: в аргументе есть намерение запомнить, но **не назван ключ** («запомни это»,
«сохрани, как сейчас»). Тогда правка не названа, а угадана: спроси, какое именно умолчание
записать, перечислив ключи из таблицы шага 2, и до ответа не сохраняй ничего.

## Шаг 1. Текущая карта

Выполни:

!`python3 ".gigacode/skills/pvm-guru/scripts/guru_profile.py" show`

Скрипт офлайн, в сеть не ходит. Он печатает один JSON: `status`, `path`, `updated_at`,
`profile` и, если есть что сказать, `notes`. Разбери `status` — это четыре разных разговора:

- `ok` — профиль есть. Покажи заполненные ключи одним сообщением (человеческими словами,
  не сырым JSON) и назови момент последнего сохранения. Поля `issues` у этого статуса не бывает:
  файл со значениями, не прошедшими проверку, приходит статусом `corrupt`.
- `missing` — профиля нет. Скажи это прямо и предложи два пути: собрать умолчания разговором
  здесь либо пройти `/guru-start`, где тот же шаг идёт вместе с картой возможностей.
- `corrupt` — файл не проходит проверку (причина в `reason`). Операции навыка идут без профиля,
  но чинится это, как правило, одной командой. Пришло поле `issues` — файл разобран, негодны
  только названные в нём ключи: `set` и `unset` перезапишут файл, сохранив годные ключи, применив
  правку и выбросив негодные значения (их вернёт `dropped_invalid`). Предложи задать эти ключи
  заново — одним `set` вместе с остальной правкой. Пришло поле `broken_stamp` — испорчен штамп
  (`version`, `updated_at`), который выставляет само семейство: задавать его человеку нечем и
  незачем, любая запись профиля перепишет его сама (годится и `unset` штампа, и `unset` любого
  ключа). Скажи это одной строкой и не предлагай `reset` ради одного штампа. Нет ни `issues`,
  ни `broken_stamp` — файл не разбирается как JSON-объект вовсе (в `reason` `not valid JSON`,
  `top-level value is not a JSON object` или `cannot read file`), и вот тогда `set`/`unset`
  откажут: предложи либо поправить файл руками по пути из `path`, либо сбросить профиль —
  по протоколу из раздела «Сброс».
- `unsupported` — версия схемы в файле новее той, что понимает установленный навык.
  Не пытайся его чинить правками: предложи обновить семейство или сбросить профиль.

Если в ответе есть `secret_like_keys` — скажи, что в файле оказались секретоподобные ключи:
они не применяются и будут удалены при ближайшем сохранении. Сами значения не печатай.

## Шаг 2. Что менять

Задай **один** вопрос: что поправить. Варианты предлагай по делу — незаполненные ключи
из таблицы ниже и «ничего, всё верно». Не вываливай всю таблицу списком: три-четыре
варианта и свободный ввод.

Ключи профиля (точечные имена — то, что понимает скрипт):

| Ключ | Что это | Значение |
| --- | --- | --- |
| `login` | логин в трекере | латиница, цифры, точка, дефис, подчёркивание, до 64 символов |
| `role` | производственная роль | один из: `manager`, `analyst`, `architect`, `developer`, `tester`, `writer`, `other` |
| `task_tracker.primary_space` | основное пространство | код: заглавные латинские буквы и цифры, 2–20 символов |
| `task_tracker.spaces` | пространства в поле зрения | список кодов через запятую |
| `task_tracker.default_suit` | тип задачи по умолчанию | код типа: латиница, цифры, подчёркивание |
| `task_tracker.product` | продукт | строка до 64 символов |
| `task_tracker.components` | компоненты | список строк через запятую |
| `source_control.tenant` | tenant SourceControl | UUID |
| `source_control.project` | проект SourceControl | латиница, цифры, дефис, подчёркивание |
| `source_control.repos` | репозитории, с которыми человек работает | список имён через запятую |
| `sberworks.jira_project` | ключ проекта Jira | заглавные латинские буквы и цифры |
| `sberworks.confluence_space` | ключ пространства Confluence | заглавные латинские буквы и цифры |

Значения не выдумывай и не «нормализуй» по смыслу: в профиль идёт то, что назвал человек.
Если он не помнит код пространства или тип задачи, предложи взять подсказки из его же данных
и **запусти вызов сам** — только когда подсказки действительно нужны:

```bash
python3 ".gigacode/skills/pvm-guru/scripts/guru_profile.py" suggest
```

Исполняемым блоком `` !`…` ``, как `show` в шаге 1, его держать нельзя: такой блок выполняется
до начала разговора, то есть и на «покажи мой профиль» тоже, — и просьба показать локальный файл
тянула бы запрос к трекеру и выборку задач человека в контекст, вопреки правилу «просмотр,
сохранение и сброс профиля в сеть не ходят».

Это единственная подкоманда, которая ходит в сеть, и только на чтение: список пространств
и выборка назначенных на него задач. Отказ трекера она отдаёт строками в `notes`, а не ошибкой, —
тогда спрашивай свободным вводом и иди дальше. Ничего никуда не записывается.

Строки `notes` пересказывай, а не пропускай. Если там сказано, что подсказки построены по одной
странице выборки, назови это одной фразой вместе с самой подсказкой: доли и порядок пространств
посчитаны по этой странице в порядке трекера, а не по всем задачам человека.

## Шаг 3. Применить

Одна правка — один запуск, все названные ключи сразу:

```
python3 ".gigacode/skills/pvm-guru/scripts/guru_profile.py" set КЛЮЧ=ЗНАЧЕНИЕ [КЛЮЧ=ЗНАЧЕНИЕ ...]
```

Списки перечисляются через запятую (`task_tracker.spaces=PVM,CRPV`). Убрать ключ:

```
python3 ".gigacode/skills/pvm-guru/scripts/guru_profile.py" unset КЛЮЧ [КЛЮЧ ...]
```

Пустое значение в `set` (`task_tracker.product=`) удаляет ключ так же, как `unset`.
Переданные ключи перезаписываются, остальные остаются как были.

Как читать ответ:

- код возврата `0`, JSON в stdout — сохранено. Поле `changed` перечисляет реально изменившиеся
  ключи по запросу. Пустое `changed` само по себе ещё не значит «ничего не поменялось»: та же
  запись могла выбросить из файла секретоподобный (`removed_secret_like`) или негодный
  (`dropped_invalid`) ключ и переписать штамп (`restamped`). Читай `notes` — там сказано, что
  именно произошло: «значения не изменились» приходит только тогда, когда файл не изменился
  ничем. Не говори «всё осталось как было» рядом с сообщением об удалении.
- код возврата `1`, JSON `{"ok": false, ...}` в stderr — **ничего не сохранено**. Причина в поле
  `error`, разбор по ключам — в `errors`. Покажи причину своими словами, предложи другое значение
  и не выдавай неудачную запись за удавшуюся.

Отдельные отказы, которые стоит объяснить, а не повторять запуск:

- ключ похож на секрет (в имени `TOKEN`, `PASSWORD`, `AUTH`, `COOKIE`, `SECRET`) — в профиле
  секретов не бывает; кред живёт в `~/.swtr-review.env` и настраивается через `/guru_doctor`;
- ключа нет в таблице выше (`tracker_login`, `task_tracker.primary-space` и прочие опечатки) —
  таблица закрыта, допустимые имена скрипт перечисляет в `known_keys`: возьми имя оттуда
  и повтори, а не выдавай отказ за сохранение;
- файл не разбирается как JSON-объект или версия схемы не поддерживается — сначала раздел
  «Сброс»; негодные значения (`issues` в `show`) отказом не являются — они выбрасываются при
  ближайшей записи и приходят в `dropped_invalid`.

`version` и `updated_at` выставляет само семейство. Отказом это не оборачивается: названный в
вызове штамп в файл не идёт, но запись проходит и кладёт текущий штамп — этим и чинится файл,
у которого испорчен ровно штамп. Скрипт называет такие ключи в `restamped` и говорит в `notes`,
что переданное значение не записано. Не выдавай это за сохранение названного значения.

## Шаг 4. Показать результат

После записи покажи получившуюся карту — её вернул тот же вызов `set`/`unset` в поле `profile`,
повторный `show` для этого не нужен. Назови изменённые ключи и путь к файлу. Если человек
назвал ещё правку — вернись к шагу 3, не перечитывая всё заново.

В конце одной строкой: остальные умолчания можно задать этой же командой в любой момент,
а разово обойти профиль — флагом `--no-profile` у скриптов навыка.

## Сброс

`reset` удаляет файл профиля целиком. Делай это **только после явного «да»** на прямой вопрос:

1. Покажи, что именно будет удалено — заполненные ключи из шага 1 и путь к файлу.
2. Спроси подтверждение отдельным вопросом. «Наверное», «давай посмотрим» и молчание —
   это не подтверждение; при любом сомнении переспроси.
3. Только после «да» выполни:

   ```
   python3 ".gigacode/skills/pvm-guru/scripts/guru_profile.py" reset
   ```

4. В ответе поле `removed` говорит, был ли файл. Скажи, что профиль сброшен, и назови,
   как собрать его заново — этой командой или через `/guru-start`.

Одиночный ключ через `reset` не убирают: для этого есть `unset`.

## Границы

Команда работает только с локальным файлом профиля. В трекер, SourceControl, Confluence и Jira
она ничего не пишет и не меняет: единственный сетевой вызов — чтение в `suggest`.

Значений не выдумывай: в профиль идёт то, что назвал человек или что вернул `suggest` с указанием
происхождения. Секретов в профиле не бывает — ни пароля, ни токена, ни строки Basic; если человек
диктует их, откажись и отправь к `/guru_doctor`. Значения секретоподобных ключей, если они всё же
оказались в файле, не печатай. Статусы и коды возврата бери из вывода скрипта, а не из головы:
если он завершился ошибкой, покажи `error` и не додумывай, что запись прошла.

Флаг `--home` есть у `show`/`set`/`unset`/`reset` и нужен только для проверки на чужом
домашнем каталоге; `--env-file` и `--timeout` есть у одной `suggest`. В обычном разговоре
ни один из них не нужен.
